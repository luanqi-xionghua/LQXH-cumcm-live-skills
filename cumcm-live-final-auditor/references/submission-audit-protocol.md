# 自包含提交终审协议

本协议是 Skill 自带的原创审计规则，不依赖作者的本机资料或历届模板。它不硬编码年度页数、大小、匿名或 AI 要求；这些项目必须由当届官方规则证明。

## 1. 冻结审计对象

开始时记录：

- 候选目录绝对路径；
- 冻结时间、版本和 SHA-256 清单；
- 主稿来源与最终 PDF；
- 题号、预期文件名和附件结构；
- 当届官方规则快照及证据位置；
- AI 使用记录位置；
- `VER-*` 重复复核报告位置及其冻结版本；
- `LAYOUT-*` 排版复核报告、源版本及其绑定的 PDF SHA-256；
- 正文起始页、附录起始页、总页数、正文实测页数和边界截图；
- 审计工具、版本和命令。

审计过程中任一候选文件变化，旧审计立即失效。修复后重新冻结并完整复审。

## 2. 规则证据矩阵

不得凭记忆判定年度规则。建立：

| 官方要求 | 证据来源与位置 | 候选证据 | 状态 |
|---|---|---|---|
| 文件名与格式 | 官方规则页/文件 | 实际文件 | `PASS/FAIL/UNVERIFIED` |
| 首页与编号 | 官方规则位置 | PDF 页码 |  |
| 匿名与身份信息 | 官方规则位置 | PDF/元数据 |  |
| 页数或大小 | 官方规则位置 | 实测值 |  |
| 代码与支撑材料 | 官方规则位置 | 目录清单 |  |
| AI 披露 | 官方规则位置 | AI 记录 |  |
| 截止与重传 | 提交系统说明 | 提交回执 |  |

任何硬性规则为 `UNVERIFIED` 时，最终状态不得为 `PASS`。

固定执行正文页数硬门：

```text
main_body_pages = appendix_start_pdf_page - main_start_pdf_page <= 30
```

没有附录时正文计到 PDF 最后一页。附录页数不设上限。正文/附录边界必须由最终 PDF 物理页和章节内容共同证明；核心模型、结果、验证、符号表或复现入口不得为规避页数被移入附录。

## 3. 严重级别

- `P0`：无法提交、违规、结论错误、身份泄露、危险文件、关键数字不可追溯或论文亮点无冻结证据；
- `P1`：明显影响可信度、复现、评阅或主要图表可读性；
- `P2`：不阻塞提交的措辞、轻微版式或可维护性改进。

每个问题都写证据、位置、影响、最小修复动作和需要复审的范围。

## 4. 双向追踪图

正向检查：

```text
题面 -> problem_contract -> model_contract -> code/config
    -> frozen output -> VER-PASS -> paper claim

model_contract -> contribution_ledger -> CONTRIB-PROVEN
              -> dedicated RID/FIG/TAB -> paper contribution claim

paper source -> rendered PDF -> LAYOUT-PASS -> final audit
```

反向检查：

```text
摘要/结论/核心表中的主张
-> RID/FIG/TAB
-> VER-PASS
-> RUN
-> code/config
-> DATA
-> 题面字段或明确假设

摘要/正文中的差异化主张
-> CONTRIB-PROVEN
-> dedicated RID/FIG/TAB/MODEL
-> frozen model/run
-> baseline expectation 与证伪实验
```

任一关键边断开就是阻塞。模型、代码和论文使用同名变量不等于语义一致，还要核对单位、方向、粒度和时间范围。

## 5. 关键数字抽样

至少从以下位置抽样：

- 摘要每个小问的关键数值；
- 每张核心表的代表值、极值或合计；
- 结论和建议中的阈值、比例、成本或提升；
- 图中转折点、峰值或区间；
- baseline 与主模型比较数字。

对每个数字检查：

1. 能定位到机器可读冻结输出；
2. 能由配置和代码复现；
3. 单位、取整和有效数字一致；
4. 汇总口径与正文描述一致；
5. 没有从图上手抄或人工改数；
6. 上游版本与最终主稿一致。

任一核心数字无法追溯，标记 `P0`。

## 6. 亮点真实性审计

先枚举摘要、引言、正文洞察、模型评价和推广中的全部差异化主张，再与当前 `contribution_ledger` 双向比对：

| 检查 | 通过条件 | 失败级别 |
|---|---|---|
| 账本存在 | 文中每条亮点都有稳定 `CONTRIB-*` | P0 |
| 状态有效 | 账本 `FROZEN`，记录 `PROVEN`，绑定当前模型冻结版本 | P0 |
| 可证伪 | `claim` 有实际执行的 `falsification_test` | P0 |
| 对照真实 | `baseline_expectation` 与实际运行使用同口径 | P0 |
| 专门证据 | `evidence_ids` 指向冻结、可复现的 `RID/FIG/TAB/MODEL` | P0 |
| 量化一致 | `proof` 可由运行产物重算，未挑最好 seed/折/情景 | P0 |
| 代价披露 | `cost_risk`、失效条件和 `fallback` 与正文一致 | P1；隐瞒会改变结论时 P0 |
| 放置一致 | `placement` 覆盖实际摘要/正文位置 | P1 |

额外反向检查：账本中的 `CANDIDATE`、`DROPPED` 或 `STALE` 不得在论文中被表述为已证明贡献。无证据亮点不得通过润色降级为模糊优点；必须删除、明确为待验证，或重新运行并冻结。

## 7. 模板指纹审计

该项由人工或 Agent 对真实成稿执行，静态目录扫描脚本不解析 PDF、Word 或 LaTeX 正文。机器可读检查项：

```text
template_fingerprint_checked: PASS / P1 / P0 / UNVERIFIED
```

### 指纹短语清单

以下内容只用于终审逐条比对，不是可复制的写作素材。命中后按 `SKILL.md` 分级，并记录论文页码、章节和连续文本范围：

1. 摘要填空骨架：`针对问题一，基于【数据和关键处理】，建立【模型/数学构造】并采用【求解方法】，得到【有 RID 的关键结果】；通过【有指标的验证】检验。`
2. 摘要同构片段：`针对问题 n：数据/处理动作 -> 模型或数学构造 -> 求解方法 -> 关键数值或决策结果 -> 验证方式与指标`
3. 结果叙事示例：`在已定义情景和约束下，方案 A 的目标值为 RID-Q2-004，相对 baseline 的变化见 TAB-Q2-002。逐约束复核未超过合同容差；当参数超过敏感性区间时，该排序可能改变。`
4. 结果闭环占位结构：`结论 -> 图表/数值证据 -> 比较 -> 解释 -> 适用范围`

逐字沿用单句或短片段为 `P1`；摘要或任一核心章节出现大段、连续成句沿用为 `P0`。同时检查问题分析、结果解释和模型评价是否机械复制手册的固定子结构顺序，或把候选配色说明文字原样写入论文。修复必须由本队依据真实模型、证据和逻辑重新表达，不得用同义词替换或机械调序；修复后重新冻结并复审。

通用章节名“问题重述、问题分析、模型假设、符号说明、模型的建立与求解、模型检验、模型评价与推广、参考文献、附录”不计为指纹，不得要求改名。未核对真实成稿或未完成清单时状态为 `UNVERIFIED`，最终结论不得为 `PASS`。

## 8. 模型与代码审计

### 数据

- 输入哈希、schema、主键、单位、范围和样本量；
- 缺失、异常、重复、合并与筛选记录；
- 时间、分组、空间和目标泄漏；
- 数据处理是否只在训练部分拟合。

### 模型

- 公式、变量、参数、目标和约束与代码一致；
- baseline 与主模型同口径比较；
- 预测有样本外验证；
- 分类有类别指标和阈值；
- 评价有权重与排名敏感性；
- 优化有逐约束复核和求解状态；
- 仿真有多 seed、区间和收敛；
- 机理模型有量纲、守恒和边界。

### 复现

- 入口、配置、依赖、版本、seed 和运行命令完整；
- 新进程重跑证据可用；
- 同版本 `VER-*` 报告为 `PASS`，且同时包含同环境复跑和不复用主求解逻辑的独立复核；
- 日志没有被忽略的致命错误；
- 输出文件与运行清单一一对应；
- 本机绝对路径、密钥和临时状态没有成为依赖。

## 9. 提交包审计

检查：

- 文件名、格式、数量、层级和压缩方式符合官方要求；
- 只有当届允许提交的 PDF、源代码、数据或支撑材料；
- 无缓存、临时文件、旧版本、自动保存、无关大文件；
- 无未知二进制、安装器、快捷方式、宏文档或符号链接；
- 无教材、论文、商业模板、第三方工具箱或许可不明数据；
- 无 API key、密码、用户名、本机路径和不应披露的身份信息；
- PDF 文件头、可打开性、页数和大小真实检测；
- 正文实测不超过 30 页，附录页数不限，正文/附录物理页边界有截图；
- 目录清单与 SHA-256 已冻结。

静态扫描脚本通过只表示目录硬检查通过，不代表内容、规则和视觉已经通过。

## 10. Word/LaTeX 源与 PDF 对应

### Word

- 最终 PDF 确实来自冻结主稿；
- 标题、题注、交叉引用、公式和目录字段已更新；
- 无修订、批注、隐藏文字、模板提示、宏依赖和个人元数据；
- 没有因字体替换、分页或导出导致内容丢失。

### LaTeX

- 保存最终编译命令和日志；
- 无缺包、缺图、未定义引用、重复标签和未解决错误；
- 字体替换与 overfull/underfull 风险已检查；
- PDF 与冻结 `.tex`、类文件、图片和参考文献对应。

同时存在两种源时，明确唯一主稿，避免误交另一份。

在检查源与 PDF 对应关系前，先验证 `layout-report.md` 状态为 `PASS/FROZEN`、绑定当前源版本和当前 PDF SHA-256，并同时包含自动预检、真实页面查看、修复后重查证据。只有 `PRECHECK_PASS`、报告已 `STALE` 或哈希不一致均为 `P0`。

## 11. PDF 逐页视觉 QA

必须查看真实渲染 PDF，至少覆盖：

- 首页、摘要、各章起始、参考文献、附录和最后一页；
- 所有跨页表、长公式、密集图和代码页；
- 页眉页脚、页码、匿名信息和空白页；
- 文字、公式和图表的裁切、重叠、乱码、孤行；
- 图例、坐标、单位、题注和小字号；
- 灰度辨识、细线和缩放后的可读性。

发现问题要记录页码、对象和截图证据，不能只写“排版有问题”。

终审需独立抽查 `LAYOUT-*` 报告中的截图与问题关闭状态，并重新查看当前 PDF 的关键页面；排版技能的 PASS 不是免检凭证。

## 12. AI 使用审计

以当届规则为准，检查：

- 工具名称、版本、时间、用途；
- 关键输入、输出、采纳与人工修改；
- 每条采纳内容对应论文、代码或图表位置；
- AI 提供的数字、引文和事实有独立验证；
- 记录不是模板示例、他人记录或事后虚构；
- 正文标注、独立说明或附件满足官方披露方式。

工具清单与记录错配、关键交互缺失或采用内容无法定位时标记阻塞。

## 13. 判定算法

只有以下项目全部满足才可 `PASS`：

```text
rules_verified
and files_valid
and no_P0
and content_traceable
and repeated_verification_pass
and same_hash_layout_pass
and main_body_pages <= 30
and page_boundary_verified
and contributions_verified
and template_fingerprint_checked == PASS
and model_validated
and reproducibility_evidence
and ai_record_compliant
and visual_qa_complete
```

否则输出 `BLOCKED`。不要使用“基本通过”“大概可提交”掩盖硬门失败。

## 14. 修复与复审

- P0 修复后完整复审规则、文件、追踪和视觉；
- P1 修复后至少复审受影响章节、结果和 PDF；
- P2 可在不引入新风险时修复；
- 临近截止优先恢复最近一次已验证可提交版本；
- 不在终审阶段引入未经 baseline、验证和复跑的新模型。

最终报告必须包含状态、规则矩阵、问题清单、关键数字抽样、亮点真实性抽样、模板指纹核对结果及命中位置、目录哈希、视觉 QA 范围、未核验项和最小下一步。
