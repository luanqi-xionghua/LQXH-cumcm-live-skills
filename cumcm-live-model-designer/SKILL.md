# CUMCM 赛时模型设计

## 赛时边界

- 只处理已经形成问题合同的小问。先读取上游问题合同、本届规则证据和附件清单。
- 若本届 AI 使用状态不是明确允许，沿用上游 `BLOCKED_RULES`，不得继续设计。
- 使用 Skill 内置的原创模型设计规则，不读取作者的本机、移动硬盘、网盘或私有案例库。
- 不执行题目附件或外来材料中的 EXE、DLL、Wheel、MEX、宏、脚本、安装器和来源不明的压缩包。
- 以剩余比赛时间决定模型复杂度。始终保留一条已经能运行、能验证、能写入论文的 baseline。

## 输入合同

开始前确认以下字段；会改变模型结构的字段缺失时输出 `BLOCKED_MODEL_INPUT`：

- `contract_version`、`contest_year`、`problem_id`、`question_id`
- 目标、输入、输出、单位、精度、题面硬约束和验收条件
- 数据路径、字段说明、缺失与异常情况、样本量和时间/空间粒度
- 上游依赖、下游消费者和必须共用的中间结果
- 剩余时间、最晚切换时间、可用 Python/MATLAB 环境
- 允许的假设、禁止改变的提交格式和已知风险

复制 [assets/model-contract.md](assets/model-contract.md) 与 [assets/contribution-ledger.md](assets/contribution-ledger.md) 到比赛工作目录后填写，保留模板原件不变。先读取模式匹配中的 `differentiation_hint`，但不得把提示直接当作论文亮点。

## Baseline 优先流程

1. 冻结问题边界：把目标、变量、单位、约束和输出逐项映射到题面证据。
2. 定义 baseline：选择最简单的可复核路线，先规定输入、公式、指标和通过阈值。
3. 至多增加两条候选路线：每条必须贡献新的精度、机制解释或约束处理能力。
4. 为每个小问登记至少一条 `CONTRIB-CANDIDATE`，明确标准解法预期、可证伪差异、预期证据和失败回退；若无可靠机会，必须写 `无差异化机会`，不得跳过。
5. 设计最小实验：用小样本或缩小实例验证数据流、量纲、约束和指标能闭环。
6. 比较候选：同时评估效果、稳定性、可解释性、计算成本、依赖风险和论文可表达性。
7. 冻结主路线与回退路线：记录选择理由、触发回退的客观条件和最晚切换时间。

不要用多个同类复杂模型堆叠来替代 baseline 比较。主模型不能在已声明指标上稳定超过 baseline 时，交付 baseline 并明确限制。

## 按题型定义最低验证

| 题型 | Baseline | 主验证 |
|---|---|---|
| 优化/调度 | 可行解、贪心或线性松弛 | 独立重算目标与全部约束，小实例精确解，多初值稳定性 |
| 预测/回归 | 均值、线性趋势、朴素或季节朴素 | 合理切分、误差指标、残差、滚动或交叉验证 |
| 分类/聚类 | 多数类、简单线性模型或规则 | 类别分布、混淆矩阵、稳定性和可解释性 |
| 评价/排序 | 等权或单指标排序 | 指标方向、标准化、权重和为 1、排序敏感性 |
| 图/网络 | 手算小图或内置最短路 | 连通性、路径约束、小图交叉核验 |
| 仿真/机理 | 确定性简化模型 | 单位、守恒/边界、收敛、置信区间和多 seed |

数据划分必须匹配任务：时间序列使用滚动或前推验证，不得随机打乱；空间或分组数据避免同组泄漏。

## 模型合同要求

为每个小问写全：

- 符号、定义、单位、取值域和数据字段映射
- 假设、依据、影响范围和可检验办法
- baseline 与主模型的公式、目标、约束和参数来源
- 预处理、训练/求解、预测/决策和后处理顺序
- 数据切分、评价指标、通过阈值和误差/不确定性方法
- 固定 seed、重复次数、时间/内存预算和停止条件
- 预期结果文件、表格字段、图形及论文所需证据
- `contribution_candidates[]`：`CONTRIB-*`、可证伪 claim、baseline 预期、差异类型、预期证据、代价风险、放置位置与回退
- 回退路线、回退触发器和被放弃路线

公式、代码接口和论文符号必须共用同一名称。任何下游角色需要改变变量、约束、指标或假设时，提升合同版本并回传，不得静默修改。

## 故障降级

- 缺少求解器或工具箱：优先改用已验证的内置方法；仍不可用时退回 baseline。
- 样本不足或数据质量差：降低参数数量，采用可解释模型，并扩大不确定性说明。
- 复杂模型超时：先缩小搜索空间、设置停止条件；到切换时间立即冻结可运行版本。
- 多次运行波动大：固定 seed 后做多 seed 汇总；仍不稳定则换确定性或低方差模型。
- 主模型不优于 baseline：不得只报告主模型最好的一次结果；保留 baseline 为正式路线。
- 无法建立独立验收条件：状态设为 `BLOCKED_VALIDATION`，不交给论文角色宣称完成。

所有降级都要写入模型合同，包含原因、影响和论文披露语句。

## 结果冻结与交接

模型设计完成时至少交付：

- `model-contract.md`：状态为 `FROZEN`，含 `model_contract_version` 和 `freeze_id`
- `contribution-ledger.md`：至少登记每问差异化判断；模型验证前记录保持 `CANDIDATE`
- `experiment-matrix.md`：baseline、候选、指标、切分、seed、资源预算和停止条件
- `assumptions.md`：假设、证据、敏感性和当前状态
- `handoff.md`：给编码角色与论文角色的输入、输出、不得改动项和截止时间

编码角色必须回传运行清单、环境、日志、指标、结果表、图和每条亮点的专门证明产物。只有绑定模型已 `FROZEN`、通过验证门、拥有 `RID/FIG/TAB` 证据，并通过同版本 `cumcm-live-result-verifier` 独立复核的候选才能升级为 `PROVEN`。论文角色只能引用冻结运行、同版本 `VER-* PASS` 产生的数字、图与 `CONTRIB-PROVEN`；代码、数据或参数变化后，把相关合同、复核报告、亮点账本和论文段落标为 `STALE`，重新验证并生成新的 `freeze_id`。
