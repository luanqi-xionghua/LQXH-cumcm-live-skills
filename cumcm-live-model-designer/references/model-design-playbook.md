# 模型设计与冻结手册

本手册提供自包含的原创设计规则。它不读取外部案例库，不替代本届题面、数据或运行证据。先从 `pattern_matches` 取得候选族，再在这里把候选变成可编码、可验证的模型合同。

## 1. 模型阶梯

每个小问最多保留三层：

1. **Baseline**：简单、透明、可运行、可独立复核；
2. **主模型**：必须明确改善精度、机制解释或约束处理；
3. **增强模型**：只有主模型通过后且时间充足才加入。

先写 baseline 的公式、指标和通过线，再讨论复杂模型。复杂度本身不是贡献。

同时为每个小问执行一次差异化登记：

1. 写出评委或透明标准解法的默认预期；
2. 登记至少一条 `CONTRIB-CANDIDATE`，说明可证伪差异、证伪结果、预期证据、代价和回退；
3. 若没有可靠差异化机会，明确写 `无差异化机会` 并将记录设为 `DROPPED`；
4. 不允许跳过登记，也不允许把复杂模型名称直接当成亮点。

## 2. 数学模型的统一语法

按顺序定义：

- 集合与索引；
- 已知参数及来源；
- 状态变量、观测变量和决策变量；
- 变量取值域、单位和上下界；
- 目标函数或估计准则；
- 题面硬约束；
- 团队假设产生的约束；
- 状态转移、边界与初始条件；
- 论文与代码需要的输出。

建议使用字段映射表：

| 数学符号 | 含义 | 单位 | 数据字段/来源 | 代码变量 | 可否估计 |
|---|---|---|---|---|---|

代码接口、公式和论文必须共用同一语义。下游若改变变量或单位，提升合同版本。

## 3. 候选选择矩阵

| 条件 | 优先选择 | 警惕 |
|---|---|---|
| 小样本、解释优先 | 低参数模型、规则、线性/广义线性 | 深层或高自由度模型 |
| 明显时序 | 朴素/季节朴素、指数平滑、低阶时序 | 随机切分、未来特征 |
| 分组或重复测量 | 分组切分、组效应或层级模型 | 同一主体跨训练和验证 |
| 硬容量/预算/时间窗 | 规划、网络流、调度 | 只用惩罚项近似硬约束 |
| 节点—边结构 | 图算法、流、匹配 | 把图随意摊平成独立样本 |
| 随机演化或排队 | 确定性 baseline + 仿真 | 单 seed、无收敛检查 |
| 多指标排名 | 等权 baseline + 敏感性 | 指标重复、任意权重 |
| 参数不可识别 | 简化模型、区间或情景 | 增加更多未知参数 |
| 资源或依赖紧张 | 内置算法与清晰回退 | 临近截止安装复杂依赖 |

## 4. 题型最低设计

### 关系与预测

- 明确目标变量的时间点、预测步长和特征可用时间。
- 预先确定切分，所有缩放、填补、选特征只在训练部分拟合。
- Baseline 至少包含均值、线性趋势、上一期或季节同期中的适用项。
- 指标同时覆盖量级误差和方向/排序需求；长周期给区间。

### 分类与聚类

- 标签含义、类别成本和决策阈值要写入合同。
- 分类按分组、时间或空间关系切分，不平衡时不用准确率单独判断。
- 聚类要定义变量尺度、距离和簇的解释方式；稳定性差时退回规则分层。

### 评价与排序

- 指标必须可解释、方向明确且避免重复表达同一含义。
- 记录标准化、权重来源和聚合公式。
- 等权结果必须保留；扰动权重和标准化方法检查排名稳定区间。

### 优化与调度

- 先找到一个满足全部硬约束的可行解。
- 区分连续、整数、二元、顺序、网络和非线性结构。
- 写清容差、求解状态、时间限制和不可行时允许放松的约束。
- 结果由独立逻辑重算目标和每条约束；启发式不能声称全局最优。

### 动力系统与仿真

- 状态、流量、存量、转移规则、单位、初值和边界必须闭合。
- 参数数量受观测信息限制；不能识别的参数用区间/情景。
- 检查守恒、极端输入、时间步和数值收敛。
- 随机模型报告多 seed 的分布和置信区间。

## 5. 不确定性路线

按证据选择，不要无条件上复杂鲁棒模型：

| 已知信息 | 方法 |
|---|---|
| 只有合理上下界 | 区间与三情景 |
| 有可解释概率分布 | Monte Carlo 或随机模型 |
| 样本抽样误差为主 | 重抽样区间 |
| 决策必须抗最坏变化 | 鲁棒约束或最坏情景 |
| 多目标偏好不确定 | 权重/阈值敏感性与候选集 |

参数扰动必须保持题面硬约束和参数相关性。报告最脆弱参数、结论稳定区间及超出范围后的失效条件。

## 6. 验证设计

### 数据门

- 字段、单位、方向、范围和样本量正确；
- 主键与合并不产生隐式重复；
- 缺失和异常处理有依据；
- 特征在真实预测/决策时可获得。

### 模型门

- Baseline 与主模型使用相同数据和指标；
- 预测有样本外或滚动验证；
- 分类有混淆矩阵、类别指标和阈值分析；
- 评价有权重、标准化和排名敏感性；
- 优化有逐约束复核和小实例交叉检查；
- 仿真有边界、守恒、多 seed 与收敛；
- 机理模型有量纲、参数可识别和数值稳定性。

### 结论门

- 关键结论在合理参数扰动下仍成立；
- 每个数字、图和表都有预期机器可读产物；
- 失败情况和回退语句已写进合同；
- 主模型不稳定超过 baseline 时选择 baseline。

### 亮点升级门

`CONTRIB-CANDIDATE` 只有同时满足以下条件才能升级为 `PROVEN`：

- 绑定的模型合同状态为 `FROZEN`，且 `freeze_id` 与账本一致；
- 数据门、模型门和结论门中的必需检查全部通过；
- 有专门的 `RID-*`、`FIG-*` 或 `TAB-*` 运行产物，并能从新进程复现；
- `proof` 使用与 baseline 相同的数据、切分、指标、约束和统计口径；
- `claim` 的证伪实验已执行，`cost_risk`、`placement` 和 `fallback` 已填写。

任一条件失败即保持 `CANDIDATE` 或降级为 `DROPPED`，不得进入论文。

## 7. 防止数据泄漏和伪复杂度

硬性排除：

- 用未来时点计算历史样本特征；
- 在全数据上拟合填补、缩放、降维或特征选择后再切分；
- 同一实体、事件或空间邻域跨训练/验证；
- 目标变量的直接变形进入特征；
- 只报告最好 seed、最好折或最好参数；
- 多个相似模型堆叠但没有预先定义的比较；
- 先看测试集结果再修改假设与阈值，却不重新建立验证集。

## 8. 模型合同冻结字段

至少包含：

```text
model_contract_version
freeze_id
question_id
pattern_ids
symbols_and_units
assumptions
baseline
candidate_model
preprocessing
split_and_validation
metrics_and_thresholds
constraints_and_tolerances
seed_and_repetitions
resource_budget
stop_conditions
expected_outputs
contribution_candidates[]
fallback_and_trigger
known_limitations
```

只有合同状态为 `FROZEN` 才能进入编码。`contribution_candidates[]` 每问至少有一条记录，或明确写 `无差异化机会`。数据、参数、公式、指标或代码接口改变后，旧合同、亮点账本和下游论文产物立即标记 `STALE`。
