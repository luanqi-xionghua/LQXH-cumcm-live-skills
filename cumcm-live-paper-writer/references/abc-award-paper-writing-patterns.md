# 国赛 A/B/C 论文写作模式

本文件把国赛 A、B、C 题优秀论文中反复出现的有效结构提炼成原创赛时协议。它不是范文库，不复刻具体论文句式、版式、数据或结论，也不能替代当届官方规则。

## 1. 使用边界

- 只用于 A、B、C 题。
- 结构规律是写作提示，不是评分保证。
- 论文只能陈述本队实际采用且有冻结证据的模型、算法和结果。
- 不为了“像获奖论文”而增加未执行的模型、检验或图表。
- 官方格式、匿名、AI 使用和支撑材料规则始终优先。

## 2. 摘要采用“总述 + 逐问 + 总检验”

先用一至两句说明研究对象、总任务和贯穿全文的主线。随后每个小问使用同一微结构：

```text
针对问题 n：
数据/处理动作 -> 模型或数学构造 -> 求解方法
-> 关键数值或决策结果 -> 验证方式与指标
```

这是内容规格，不是句式模板；箭头顺序不代表最终句子顺序。每队必须根据本题结果自行决定开头语、句序和连接方式，不得逐字沿用上述表达或把各问写成同一套填空句。

最后补充总体稳健性、适用边界或最重要建议。摘要中的每个模型名、数字和判断都必须能回到正文的 `MODEL-*` 或 `RID-*`。

摘要第一屏必须再完成两件事：用一句话给出贯穿全文的方法主线；前置至少一条 `CONTRIB-PROVEN` 的量化结果。该亮点必须绑定当前冻结账本与专门 `RID/FIG/TAB`，不得用“创新性强”替代证据。

摘要信息预算：

- 背景只保留理解任务所必需的内容。
- 每问至少有一个具体输出，不以算法名清单代替结论。
- 只保留影响答案的模型名，不列预处理小工具。
- 验证用指标、对照或误差表达，不写“效果很好”。
- 关键词优先选择研究对象、关键机制、核心模型、求解方法或评价指标。

摘要失败信号：

- 读完仍不知道每问得到了什么；
- 方法很多但没有数字、排序、方案或规律；
- 出现正文不存在的模型或结果；
- 将可行解写成全局最优，将相关关系写成因果；
- 使用“精度高、效果显著、结果合理”但没有评价口径。
- 第一屏看不到被证明的差异，或出现账本中不存在的亮点。

## 3. 问题重述必须压缩而不是改写题面

问题重述只保留四类信息：

1. 研究对象和场景；
2. 已知数据与硬约束；
3. 各小问要求的输出；
4. 小问之间的数据或逻辑依赖。

不要逐句同义替换题面，不在重述中提前介绍算法，也不把背景材料当成团队结论。可用“输入—输出—验收口径”表锁定任务。

## 4. 问题分析要解释建模选择

每问的分析至少回答：

- 本问本质上是什么数学任务；
- 难点来自数据、机理、约束、不确定性还是计算规模；
- 为什么所选模型能够表达该难点；
- 上一问的什么产物会被复用；
- 最终用什么指标判断答案可接受。

问题分析不是方法百科。没有被正文实际使用的候选算法不展开。

## 5. 每问覆盖八类论证要素

以下八类是内容门禁，不是固定的小节名、句式或排列顺序。团队应按本问的数学依赖和证据链自行组合，不能机械复制成各问一致的“八段式”；但八类内容都必须有明确落点。

### 5.1 目标与接口

用一句话写清本问要输出的对象、格式和评价口径。若依赖上一问，列出输入的文件、变量或结果标识。

### 5.2 数据与处理

交代数据范围、单位、缺失与异常处理、标准化或特征构造。每一步说明理由和产物；不能只写“对数据进行预处理”。

### 5.3 模型建立

依次给出变量和参数、关系或机制、目标函数、硬约束、团队假设、适用条件。公式后的符号、单位和数据来源必须可追溯。

### 5.4 求解过程

将算法写成可执行步骤，至少记录初始化、关键参数、迭代或搜索逻辑、停止条件、随机种子和输出文件。复杂迭代或分支过程可用流程图，但流程图不能替代文字和参数。

### 5.5 结果展示

先展示回答题面所需的核心数字、方案、排序、预测或规律。大规模完整结果可提交为支撑材料，正文保留代表结果、汇总统计和定位方式。

### 5.6 结果解释

紧跟表图说明：

```text
结论 -> 数值/图表证据 -> 比较 -> 机制或实际含义 -> 边界
```

不能只写“由图可知”。至少指出变化方向、关键差异、约束是否满足，以及它为何支持本问答案。

#### 可选：洞察/发现

仅当账本中存在当前冻结的 `CONTRIB-PROVEN` 时增加。写作顺序为：

```text
可证伪 claim -> 专门 RID/FIG/TAB -> 相对 baseline 的量化差异
-> 机制/含义 -> cost_risk 与失效边界 -> fallback
```

这同样是内容规格，不规定成稿句序或连接方式。

必须同时显示 `contrib_id` 与 `evidence_ids`；无绑定就删除整段。

### 5.7 验证与敏感性

根据模型类型选择真实可执行的检查：

| 模型任务 | 优先验证 |
|---|---|
| 机理或几何 | 量纲、守恒、代回原式、边界值、独立求解路线 |
| 优化 | 逐约束复核、baseline、不同初值/算法、最优性边界 |
| 预测 | 留出或滚动验证、残差、MAE/RMSE/R²、区间覆盖 |
| 评价与排序 | 权重、标准化和阈值敏感性，排序稳定区间 |
| 仿真 | 多随机种子、收敛、置信区间、极端情景 |

只报告实际执行过的检验。说明指标方向、对照对象和可接受阈值。

### 5.8 小结与下问接口

用一句可直接回答题面的结论结束本问，并绑定 `RID-*`。随后注明下一问复用的变量、文件或模型部件；没有依赖时不强行添加。

## 6. 图表采用“单结论闭环”

每张图表只承担一个主要结论：

1. 正文先引用图表；
2. 给出最重要的数字或比较；
3. 解释其原因或意义；
4. 指出适用条件或不确定性。

图表必须有对象、范围、单位、图例和自足题注。预测图应区分训练与检验区间；优化图应说明可行性和目标；敏感性图应标出基准参数和稳定区间。正文没有引用或没有结论的图表应删除。

## 7. 验证使用由强到弱的证据层级

优先选择更直接的证据：

1. 代回公式、逐约束检查或人工可核算的小样本；
2. 独立算法、独立推导或独立求解路线的交叉验证；
3. 网格精度、时间步长、超参数或权重的敏感性；
4. baseline、消融或公开常识范围对比；
5. 极端情景、扰动试验、多随机种子；
6. 仅凭“符合直觉”的解释。

第 6 层不能单独构成有效验证。两条独立路线一致时，要说明比较对象、误差定义和差异量级。

## 8. 附录与支撑材料的边界

正文必须保留：

- 直接回答各小问的结果；
- 核心模型、目标和约束；
- 关键参数与求解配置；
- 至少一项有效验证；
- 完整结果或代码的定位方式。

附录或支撑材料适合放：

- 完整代码与运行说明；
- 批量明细表和中间结果；
- 冗长但可复核的推导；
- 额外敏感性图和诊断图；
- 按官方要求提交的结果文件。

不得把唯一的关键结论、唯一的验证或无法从正文定位的代码入口放在附录。

## 9. 模型评价与推广由亮点账本驱动

- 优点只来自 `CONTRIB-PROVEN`，并同时写量化证据与代价边界。
- 推广只来自 `delta_type=更好泛化` 且确实做过跨情景、跨样本或外推检验的 `PROVEN`。
- 改进方向可来自仍有价值的 `DROPPED`，但必须说明为什么被放弃、重新验证需要什么条件。
- `CANDIDATE` 不得包装成创新点；复杂度、模型数量和算法新颖名称本身都不是贡献。

## 10. A/B/C 题型提示

这些只是常见倾向，必须由当届题面决定：

- A 题常需强调机理、几何、量纲、边界条件、参数辨识和数值精度。
- B 题常需强调约束、搜索或优化过程、可行性复核、算法配置和方案解释。
- C 题常需强调数据质量、特征构造、评价口径、预测/分类验证和政策或管理含义。

若题目特征与上述倾向不符，按实际任务建模，不按题号套模板。

## 11. 来源卫生门

外部 PDF、OCR 文本、模板和网络材料在进入写作流程前必须检查：

- 广告、水印、二维码、联系方式；
- 代写、辅导、代充或“包奖”等推广话术；
- 无法确认来源的作者、机构、DOI、页码和数据；
- OCR 错字、断行、公式错识别和表格串列；
- 其他竞赛或往届规则。

这些内容一律不得进入正文、参考文献、模板、AI 使用记录或公开 Skill。OCR 只用于定位；公式、表格、数字和引文必须回看原页或原始来源。

## 12. 全局完整性门

临近截止时全局配平优先于单点最优。逐问检查：

- 有直接回答题面的实质结论；
- 有简化或正式模型、冻结结果和至少一项验证；
- 有适用边界和必要回退；
- 后问不因前问过度打磨而空白。

简化模型可以提交，但空白小问不可以。任一小问没有实质答案时，整稿标记 `BLOCKED`。

## 13. 终稿反模式检查

出现以下任一情况就退回修改：

- 重述接近逐句复制题面；
- 问题分析只罗列算法名；
- 公式很多但没有说明它解决哪个困难；
- 算法没有参数、停止条件或输出；
- 结果只有表图，没有正文结论；
- 结论没有数值、比较或证据标识；
- 声称准确、稳健或最优但没有验证；
- 摘要与正文的模型名或数字不一致；
- 核心结果只在附录或支撑文件中；
- 附录堆放代码却没有运行入口；
- 污染广告、联系方式或模板示例残留；
- 为了完整而虚构未执行的模型或检验。
- 用 `CANDIDATE`、无证据亮点或复杂模型名称冒充贡献。
- 前问非常完整但存在没有实质答案的空白小问。
