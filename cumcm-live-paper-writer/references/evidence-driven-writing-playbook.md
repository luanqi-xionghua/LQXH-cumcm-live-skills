# 证据驱动的赛时论文成稿手册

本手册是 Skill 自带的原创写作协议，不包含获奖论文句式、教材段落或商业模板正文。它规定如何把团队真实的冻结结果转化为论文，不能生成或替代实验结果。

## 1. 建立证据账本

每个关键对象使用稳定标识：

| 类型 | 标识 | 最低证据 |
|---|---|---|
| 问题 | `Q-*` | 题面位置与合同版本 |
| 数据 | `DATA-*` | 文件、字段、单位、哈希 |
| 模型 | `MODEL-*` | 合同、公式、假设、版本 |
| 运行 | `RUN-*` | 配置、环境、seed、日志 |
| 复核 | `VER-*` | 同环境复跑、独立重算、硬门和冻结版本 |
| 结果 | `RID-*` | 机器可读文件与定位 |
| 图 | `FIG-*` | 图源数据与生成命令 |
| 表 | `TAB-*` | 表源数据与生成命令 |
| 亮点 | `CONTRIB-*` | 当前冻结模型、专门运行证据、量化差异与代价边界 |
| 引文 | `CIT-*` | 来源与支撑陈述 |
| AI 记录 | `AI-*` | 工具、用途、交互、采纳 |

维护映射：

```text
论文位置 -> 证据 ID -> 文件/页码/单元格/命令 -> 冻结版本
```

没有证据 ID 的关键数字不得进入摘要、核心表或结论。

## 2. 建立亮点账本

`verification_report` 回答“首次结果是否经重复与独立方法复核”，`evidence_ledger` 回答“每个数字是否真实”，`contribution_ledger` 回答“本文相对透明 baseline 的差异是否已经被证明”。三者缺一不能把相关结果或亮点写入论文。

每条 `CONTRIB-*` 必须包含可证伪 `claim`、`baseline_expectation`、`delta_type`、`falsification_test`、`evidence_ids`、量化 `proof`、`cost_risk`、`status`、具体 `placement` 和 `fallback`。规则：

- `evidence_ids` 为空立即 `DROPPED`；
- 绑定模型未 `FROZEN` 或验证门未通过，保持 `CANDIDATE`；
- 只有 `PROVEN` 能进入摘要、正文洞察和模型优点；
- 数据、模型、代码或证据变化后，账本与引用位置一起标记 `STALE`；
- 写不出什么结果会推翻 `claim`，或只有好处没有代价，不得视为亮点。

论文追踪图使用：

```text
model_contract ─┬─> run_manifest ───────────────────────┐
                └─> contribution_ledger (CANDIDATE) ────┤
                                                        └─> verification_report
                                                             ├─> evidence_ledger ─────────────────────┐
                                                             └─> contribution_ledger (PROVEN/DROPPED) ┴─> paper
```

## 3. 论文总结构

具体格式服从当届官方规则。内容通常按以下逻辑组织：

1. 问题重述与交付目标；
2. 问题分析与总体路线；
3. 模型假设及影响；
4. 符号、单位和数据说明；
5. 各小问的模型、求解、结果和检验；
6. 敏感性、稳健性和边界；
7. 模型评价与可执行建议；
8. 参考文献、AI 使用说明和附录。

章节顺序可以调整，但证据链不能断。

## 4. 每小问写作单元

逐问覆盖以下八类内容：

1. **目标与接口**：准确回答题面要求，并说明与前后小问的依赖；
2. **数据**：说明范围、字段、单位和处理；
3. **方法**：解释为什么选 baseline 与主模型；
4. **模型**：变量、参数、公式、目标、约束、边界；
5. **求解**：配置、环境、seed、停止条件；
6. **结果与解释**：数字、图表、比较、机制或实际含义；
6A. **洞察/发现（可选）**：只写 `CONTRIB-PROVEN`，同时引用 `contrib_id` 与其 `evidence_ids`；
7. **验证**：代回/约束复核、独立路线、敏感性或 baseline；
8. **边界与下问接口**：稳定区间、失效条件、回退和复用产物。

以上是内容规格，不是固定的小节名、句式或排列顺序；团队须按本问的数学依赖自行组织，不得逐字沿用或把各问机械排成同一结构。八类内容不得缺失，模型定义、结果证据和验证之间的逻辑先后仍须清楚。

每个小问结束时明确一句可回答题面的结论，并绑定 `RID-*`。

## 5. 摘要反写

摘要最后写，只使用已冻结结果。每个小问用四要素：

```text
针对什么 -> 建立/执行什么 -> 得到什么关键结果 -> 如何验证
```

这是内容规格，不是句式模板；箭头只列必含信息，不代表句子顺序。开头语、句序和连接方式由本队根据真实结果决定，不得逐字沿用。

摘要避免：

- 大段背景或空泛意义；
- 只罗列算法名；
- 正文没有出现的数字；
- “效果很好”“结果准确”等无指标评价；
- 把相关关系写成因果；
- 把可行解写成全局最优。

摘要第一屏还必须让评委看到至少一条 `CONTRIB-PROVEN` 的量化 `proof`，并用一句话给出贯穿全文的方法主线。若只读第一屏看不见“被证明的差异”，退回重写。

## 6. 数学表达

- 符号首次出现即定义，给单位和取值域。
- 同一符号不复用；向量、矩阵、集合和标量样式一致。
- 目标函数与所有关键约束完整呈现。
- 题面硬约束与团队假设分开说明。
- 公式后的参数能回到数据字段或估计步骤。
- 代码变量与论文符号通过映射表对应。
- 有容差、边界或初值时明确写出。

## 7. 结果叙事

每个核心结果使用：

```text
结论 -> 图表/数值证据 -> 比较 -> 解释 -> 适用范围
```

示例结构：

> 在已定义情景和约束下，方案 A 的目标值为 `RID-Q2-004`，相对 baseline 的变化见 `TAB-Q2-002`。逐约束复核未超过合同容差；当参数超过敏感性区间时，该排序可能改变。

实际成稿使用团队真实证据。不要把示例句当结果，也不得沿用该示例的句式结构；它只用于说明证据完整度，不是可复制的写法。

洞察段在上述闭环之后增加：

```text
CONTRIB-PROVEN claim -> 专门 RID/FIG/TAB -> 为什么不同于 baseline
-> cost_risk/失效边界 -> fallback
```

无冻结 `CONTRIB-*` 或无专门证据时省略洞察段。

## 8. 图表协议

每张图或表必须：

- 只承担一个主要结论；
- 标明对象、时间范围、单位、图例和不确定性；
- 在正文先引用再解释；
- 有可读字号和灰度可辨识编码；
- 与机器可读源数据和生成代码关联；
- 编号连续且题注自足；
- 不手工改数或仅保留截图。

坐标轴截断、双轴、对数尺度、平滑或归一化会改变理解时，必须明确说明。

## 9. 误差、稳健性与局限

只写真实执行过的检查：

- 预测：样本外误差、残差、区间覆盖；
- 分类：类别指标、阈值、误判；
- 评价：权重、标准化与排名敏感性；
- 优化：目标和约束独立复核、最优性边界；
- 仿真：多 seed、置信区间、收敛；
- 机理：量纲、守恒、参数可识别和边界。

局限应对应机制，例如“外生变量在预测期不可获得”或“参数只在给定区间可识别”，而非空泛写“数据较少”。

## 10. 模型评价与推广

模型评价不再从套话起草，而从亮点账本生成：

- 优点：当前 `PROVEN` 记录的 `claim + proof + cost_risk`；
- 推广：只取 `delta_type=更好泛化` 且已有跨情景、跨样本或外推验证的 `PROVEN`；
- 改进：取仍有价值的 `DROPPED` 候选，说明被证伪/放弃原因、重新验证条件和回退。

不得把 `CANDIDATE` 改写成优点，也不得把只在原样本成立的结果写成泛化。

## 11. 引文协议

引文表至少记录作者/机构、标题、出处、访问日期、论文位置和支撑陈述。原则：

- 引文紧邻它支撑的事实或方法来源；
- 不用二手转述替代可取得的一手来源；
- 动态数据记录访问时间和版本；
- 算法常识不代替本届数据证据；
- 不虚构 DOI、作者、页码或结论。

## 12. AI 使用记录

以当届官方规则为准。每条真实记录包含：

- 工具与使用时显示的版本；
- 时间与时区；
- 用途和阶段；
- 足以审计的关键输入与输出；
- 采用、弃用和人工修改；
- 影响的论文、代码、图表或分析位置；
- 人工验证方式。

模板中的示例工具、提示词和采纳说明不能当作真实记录。

## 13. Word 与 LaTeX 路线

### Word

- 使用样式、题注、交叉引用和公式对象；
- 清除修订、批注、占位符、隐藏文字和个人元数据；
- 不启用宏，不让手工编号替代自动字段；
- 从冻结主稿导出 PDF。

### LaTeX

- 使用最小主文件、唯一标签、自动引用和可复现编译命令；
- 检查缺图、缺包、未定义引用、重复标签、字体和 overfull box；
- 图片名和路径稳定，保存编译日志；
- 从冻结源文件生成 PDF。

只设一份内容母版和一条主路线。另一格式若保留，必须从同一冻结内容生成并做差异核对。

## 14. 成稿一致性门

交给终审前确认：

- 题号和小问顺序正确；
- 摘要、正文、图表和结论的模型名与数字一致；
- 符号、单位、时间范围、样本量和有效数字一致；
- 所有图、表、公式、章节和引文被引用；
- 结果均来自 `FROZEN` 运行；
- 结果均绑定同版本 `VER-* PASS`，且复跑与独立复核两轮完整；
- 摘要和正文亮点均存在于当前 `FROZEN` 亮点账本，且状态为 `PROVEN`；
- 每个小问都有可提交的实质答案；任一小问空白则整稿 `BLOCKED`；
- 占位符、模板提示、示例数据、批注和修订已清除；
- PDF 已真实渲染并逐页检查；
- 当届规则与 AI 记录已有可审计证据。

发现冲突时回到证据源修正，不凭“更合理”手工改写冻结数字。
