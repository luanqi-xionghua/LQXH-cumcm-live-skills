# CUMCM 赛时论文成稿

## 总原则

- 仅在比赛进行中使用本技能推进赛时成稿；不把它变成长期学习计划。
- 本技能只面向国赛 A、B、C 题；不得把 D、E 题或其他竞赛的写作习惯混入正文。
- 先取得并记录当届官方规则、通知或提交系统要求。官方规则与内置经验冲突时，以官方规则为准。
- 先冻结结果，再写结论。未冻结的数值只能写成明确占位符，不得猜测、补齐或润色成确定事实。
- 只写团队实际采用、能够解释且有结果证据的模型。不得为显得复杂而堆叠模型。
- 采用一个内容母版和一条主排版路线，避免 Word、LaTeX 两份正文各自漂移。
- 正文最终不得超过 30 页，附录页数不设上限；任何更严格的当届官方要求仍优先。
- 不执行外来 `.exe`、`.lnk`，不启用 Office 宏；不把其他竞赛规则混入国赛论文。

开始前按需读取：

- 证据驱动成稿与一致性协议：[references/evidence-driven-writing-playbook.md](references/evidence-driven-writing-playbook.md)
- A/B/C 优秀论文的原创结构提炼：[references/abc-award-paper-writing-patterns.md](references/abc-award-paper-writing-patterns.md)
- A/B/C 图表选择、风格与视觉 QA：[references/abc-figure-design-playbook.md](references/abc-figure-design-playbook.md)
- 原创论文骨架：[assets/cumcm-paper-skeleton.md](assets/cumcm-paper-skeleton.md)
- 上游亮点账本模板：[../cumcm-live-model-designer/assets/contribution-ledger.md](../cumcm-live-model-designer/assets/contribution-ledger.md)

## 1. 建立赛时事实表

收集并冻结以下输入：

1. 当届官方规则快照、来源链接或用户提供的规则文件。
2. 题号、每小问要求和最终交付格式。
3. 已采用模型、假设、参数、求解器与软件版本。
4. 最终代码、数据快照、运行命令、随机种子和输出文件。
5. 最终数值、图、表、误差分析、敏感性分析和模型检验。
6. 与最终运行同 `freeze_id/run_id` 的 `VER-* PASS` 重复复核报告。
7. 引用来源及其实际支撑的陈述。
8. AI 工具名称、版本、时间、用途、关键交互、采纳内容、人工修改和论文位置。
9. 下游排版复核报告位置与预期 `LAYOUT-*` 标识。
10. 页数边界：最终 PDF 的正文起始物理页、附录起始物理页、正文实测页数和总页数。

为每项证据分配稳定标识：

- 结果：`RID-Q1-001`
- 图：`FIG-Q1-001`
- 表：`TAB-Q1-001`
- 复核：`VER-Q1-001`
- 亮点：`CONTRIB-Q1-001`
- 引文：`CIT-001`
- AI 记录：`AI-001`

建立“论文位置 → 证据标识 → 源文件/页码/单元格/运行命令”的溯源表。没有证据标识的关键数字不得进入摘要或结论。

同时读取上游 `verification-report.md` 与 `contribution-ledger.md`。只有复核报告状态为 `PASS` 且绑定当前冻结版本的结果才能写入论文；只有账本状态为 `FROZEN`、记录状态为 `PROVEN`、绑定同一 `VER-* PASS` 与专门 `RID/FIG/TAB` 证据的亮点才能写入论文。不得在写作阶段新造 `CONTRIB-*`。

## 2. 执行结果冻结门

逐小问确认：

- `verification-report.md` 状态为 `PASS`，其 `model_freeze_id/run_id` 与最终代码和结果完全一致。
- 模型版本与代码提交点已经冻结。
- 正文将引用的结果能由冻结代码和数据复现。
- 图表来自冻结结果，不是手工改数后的副本。
- 单位、有效数字、置信区间或误差口径已经统一。
- 异常结果已经解释，未被静默删除。
- 每条准备写入论文的 `CONTRIB-PROVEN` 已绑定当前冻结模型、专门运行产物、量化 `proof`、`cost_risk` 和 `fallback`。

任一项未通过时，保留形如 `【待复核：VER-Q2-001 / RID-Q2-003】` 的占位符，并把该段标成阻塞；不得伪造确定性陈述。

## 3. 用骨架完成正文

复制 `assets/cumcm-paper-skeleton.md` 到比赛工作目录作为原创内容骨架，不复制外来论文或商业模板正文。

按以下顺序成稿：

1. 先写每小问的“目标与难点—数据—模型—求解—结果—解释—验证—下问接口”。
2. 再写模型假设、正文符号说明表、总体评价和附录说明。
3. 用已经冻结的每小问结论反写摘要。
4. 最后完成标题、关键词、参考文献和 AI 使用说明。

写作要求：

- 问题分析解释为什么选择该方法，不提前偷放结果。
- 模型建立说明变量、参数、目标、约束、适用边界和求解过程。
- “符号说明”必须是正文独立章节，固定放在“模型假设”之后、“数据与预处理/模型建立”之前；不得只放在附录、脚注或支撑材料。
- 正文符号表至少包含“符号、含义、单位、取值范围/类型、首次出现位置”。全文共用或反复使用的符号必须进入该表；只在单个公式附近出现一次的局部符号可就近定义。
- 即使符号已经进入正文表，每个关键公式首次出现时仍要在相邻正文解释本式新增符号、下标、上标、集合和单位，不能要求评委反复翻表猜含义。
- 每个小问至少形成一次“结论—图表/数值证据—机制解释—适用边界”闭环。
- 若增加“洞察/发现”层，必须引用一个 `CONTRIB-PROVEN` 及其 `evidence_ids`；无绑定就删除，不得改写成普通赞美。
- 每张图表只承担一个主要结论，正文必须实际引用并解释其含义。
- 摘要中的模型名、数值和结论必须与正文完全一致。
- 优缺点必须对应真实设计和检验，不写空泛套话。
- 引文必须支撑相邻陈述；不得只列参考文献而不在正文引用。

## 4. 执行 A/B/C 写作质量门

摘要最后反写。开头只交代研究对象和总任务；随后按小问写明“采取了什么处理、建立了什么模型、如何求解、得到什么关键结果、如何验证”。摘要第一屏必须出现至少一条 `CONTRIB-PROVEN` 的量化结果，并用一句话交代贯穿全文的方法主线。关键词使用研究对象、机制、模型或算法的具体名称，不写“数学建模”等空词。若摘要只是罗列算法、没有结果数字或可核验结论，退回重写。自检反问：“评委只读这段摘要，是否能看见一条被证明的差异，并理解为什么值得继续读？”答不上来就退回重写。

每个小问正文必须覆盖以下内容并形成闭环。小节名、组合方式和排列顺序由本问的数学逻辑与证据链决定，不得把清单机械复制成各问相同的固定子结构；但模型必须先定义后使用，结果必须有证据和验证：

1. 明确本问输出、难点及与上一问的依赖。
2. 说明数据、变量、假设及方法选择理由。
3. 建立公式、目标、约束或统计关系。
4. 给出足以复现的算法步骤、参数和停止条件。
5. 先展示核心表图或数值，再用正文回答题面。
6. 解释结果产生的机制、差异或实际含义。
6A. 可选“洞察/发现”：只写 `CONTRIB-PROVEN`，同时标出 `contrib_id` 与 `evidence_ids`；没有冻结绑定则省略本层。
7. 至少完成一种真实验证，并说明失效边界。
8. 若后续小问复用本问产物，明确输出接口。

验证优先级从直接到间接依次为：代回原式或逐约束复核、独立算法或独立求解路线交叉验证、参数与离散精度敏感性、baseline/消融比较、极端情景和随机重复。只能写实际运行过的验证；不得用“结果较好”“误差较小”代替指标。

正文必须保留支撑核心结论的最小证据。完整代码、批量中间表和冗长推导可放附录或支撑材料，但不得把唯一的关键结果、验证结果或复现入口藏在附录。

执行 30 页预算门：

- 初稿正文目标控制在 27–28 页，为浮动体、交叉引用和最终导出预留 2–3 页缓冲。
- 最终正文页数按 PDF 物理页计算：`附录起始页 - 正文起始页`；没有附录时计算到 PDF 最后一页。
- 附录页数不限，但不得为了规避 30 页限制，把回答题面所必需的模型、核心结果、关键验证、符号说明或复现入口搬到附录。
- 超页时按“删重复说明 → 合并低信息密度图表 → 压缩非关键推导 → 将可展开材料移入附录”的顺序处理。
- 不得用小于当届要求的字号、异常行距、缩窄页边距、不可读图表或隐藏文字强行压页。

模型评价与推广由亮点账本驱动：优点只写 `PROVEN` 亮点及证据；推广只写 `delta_type=更好泛化` 且通过外推/跨情景验证的记录；改进方向可来自有价值的 `DROPPED` 候选，但必须说明被放弃原因和重新验证条件。

来源材料先过卫生门：OCR 文本层、模板或参考论文中的广告、水印、二维码、联系方式、代写辅导和“包奖”话术一律视为污染，不得进入正文、参考文献、模板或 AI 记录。OCR 结果只能用于检索，关键内容必须回看原页。

## 5. 执行图表设计门

先为每张候选图写一句“本图要证明什么”。无法写出明确结论的图不进入正文。按任务选择图型，不以“更丰富”为理由添加装饰图：

- A 题优先考虑几何/机理示意、坐标与边界、空间分布、参数场、数值精度和守恒误差。
- B 题优先考虑算法流程、可行域/路径/排程、目标收敛、方案对比、Pareto 前沿和敏感性。
- C 题优先考虑数据质量、分布、相关结构、分组比较、时序、预测误差和决策结果。

同一论文使用统一视觉语法：团队在开始出图前从 `SET-A` 至 `SET-D` 四组已验证候选中显式选择一组，在 `run-manifest` 记录 `palette_set`，全文不得逐图换组或随机切换。同一对象始终使用同一颜色、线型和标记。颜色不能作为唯一编码，必须用线型、标记、纹理或直接标签保证灰度和色觉缺陷下仍可区分。多子图共享图例、单位和轴范围，并标注 `(a)(b)(c)`。关键点、基准线、可行边界、置信区间和最优点直接标注，避免读者来回查图例。

禁止 3D 饼图、彩虹色带、无说明的双纵轴、未经声明的平滑、没有轴断裂标识的截断坐标、只画拟合线不画原始点，以及缩到最终版后文字不可读的多子图。柱状图原则上从零起；若非零起点对判断确有必要，改用点图/区间图或清楚标出轴断裂。

每张图必须绑定 `FIG-*`、图源数据、生成代码/命令和冻结运行。优先同时导出矢量 PDF/SVG 与 300 dpi 以上 PNG；白色背景、ASCII 文件名、最终插入尺寸下字号不小于约 8 pt。插入论文后必须从真实 PDF 检查字体、线宽、图例、颜色、裁切和灰度可辨识性。

图表登记中记录同一个 `palette_set`。除非连续科学色带的可读性要求无法由所选组派生的顺序/双向色带满足，不得另用配色；例外必须写明理由并完成灰度、色觉缺陷和打印 QA。

## 6. 维护引用与 AI 记录

引用表至少记录：

| 字段 | 要求 |
|---|---|
| 引文标识 | `CIT-###` |
| 作者/机构 | 原始来源责任者 |
| 标题 | 论文、标准、网页或数据集标题 |
| 来源位置 | DOI、URL、出版信息或本地文件页码 |
| 访问日期 | 适用于网页和动态数据 |
| 支撑陈述 | 论文中的准确位置 |

AI 使用表至少记录：

| 字段 | 要求 |
|---|---|
| 记录标识 | `AI-###` |
| 工具与版本 | 使用时实际显示的名称和版本 |
| 时间 | 含时区 |
| 用途与环节 | 例如代码排错、措辞修改 |
| 关键输入与输出 | 保留足以审计的原始记录 |
| 采纳与人工修改 | 明确采用、弃用和修改内容 |
| 论文位置 | 节、图、表、公式或附录 |

不得把示例模板中的工具名、提示词、回复或采纳说明当成团队真实记录。当届规则不允许某种 AI 用法时，立即停止该用法并保留合规记录。

## 7. 选择排版主路线

### Word 路线

- 只在模板工作副本上操作，绝不覆盖来源文件。
- 优先使用 `.docx`；旧 `.doc` 先在禁用宏的环境中转换。
- 使用标题样式、题注、交叉引用、自动编号和公式对象。
- 不用截图代替公式，不手工输入图表编号。
- 保留一份无修订痕迹、无批注、无个人元数据的提交候选稿。

### LaTeX 路线

- 只把经检查的模板解压到隔离工作目录。
- 新建最小化主文件，不沿用带推广内容的示例正文。
- 根据模板要求使用 XeLaTeX 或 `latexmk -xelatex`，保存完整日志。
- 使用 ASCII 图名、唯一标签、自动交叉引用和三线表。
- 把缺图、缺包、未定义引用、字体替换、overfull/underfull 警告列入修复队列。

如用户要求同时保留 Word 与 LaTeX，指定其中一个为唯一主稿；另一份只能从同一冻结内容生成，并对两个最终 PDF 做逐项差异核对。

## 8. 执行内容一致性检查

交叉核对：

- 题号、小问顺序与题面一致。
- 正文存在位于“模型假设”之后、建模章节之前的符号说明表；没有把完整符号表只放在附录。
- 符号首次出现有定义，同一符号不复用为不同含义；正文表中的含义、单位、取值范围与公式附近解释一致。
- 单位、时间范围、样本量、有效数字和指标方向一致。
- 摘要、正文、图、表、结论和附录的关键数值一致。
- 所有关键结果都能定位到同版本 `VER-* PASS` 报告中的 Round A、Round B 和题型硬门。
- 摘要与正文中的 `CONTRIB-*` 均存在于当前冻结账本，`claim`、`proof`、`cost_risk` 和 `placement` 一致。
- 图、表、公式、章节和参考文献编号连续且均有引用。
- 代码文件名、入口命令和输出文件与附录清单一致。
- 所有占位符、模板提示语、批注、修订和示例数据均已清除。

发现冲突时回到证据源修正，不以“看起来更合理”为由改写冻结结果。

## 9. 渲染并交接独立排版复核

必须检查真实渲染 PDF，不能只检查源文件或文本提取结果。

成稿阶段先做一次基础逐页检查：

- 首页、摘要、每个章节起始页、参考文献和附录完整。
- 无裁切、重叠、乱码、空白页、孤行、异常分页或字体替换。
- 图表清晰，字号可读，图例、坐标、单位和颜色含义完整。
- 公式未截断，编号位置正确，跨页表格表头和续表合理。
- 页眉页脚、页码、匿名信息和文件元数据符合当届规则。

随后调用 `cumcm-live-layout-verifier`，由其对当前 Word/LaTeX 源、编译日志和真实 PDF 执行自动预检、逐页视觉检查以及“修复—重新生成—从头重查”闭环。排版报告必须绑定当前 PDF SHA-256；论文、图表、字体或导出设置变化后，旧 `LAYOUT-* PASS` 立即失效。

只有取得当前版本 `LAYOUT-* PASS` 后，才能调用 `cumcm-live-final-auditor` 对提交目录执行独立终审。在终审通过前，不宣称“可提交”。

## 完成条件

仅当以下条件同时满足时结束：

- 当届官方规则已记录并应用。
- 全部关键结论均有冻结结果和溯源标识。
- 全部关键结论均绑定同版本 `VER-* PASS`；报告 `STALE/BLOCKED` 时论文不得完成。
- 每个小问都有可提交的实质答案；简化模型也必须回答题面并写明边界，任一小问空白则状态为 `BLOCKED`。
- 摘要与正文中的亮点均为当前账本的 `CONTRIB-PROVEN`。
- 引用与 AI 使用记录完整。
- Word 或 LaTeX 主路线已成功生成最终 PDF。
- 正文符号说明表位置正确、字段完整，并已逐项核对公式附近定义；只在附录提供符号表时状态为 `BLOCKED`。
- 当前最终 PDF 的正文实测页数不超过 30；附录页数不限制，但正文/附录边界和物理页码已写入 `LAYOUT-*` 报告。
- 所有论文图使用同一个已显式选择并登记的 `palette_set`，同对象跨图颜色一致，并通过灰度/色觉缺陷可辨识性检查。
- 当前 PDF 已取得同 SHA-256 的 `LAYOUT-* PASS`，其中自动预检与逐页视觉 QA 均已完成。
- 没有未解决占位符或阻塞项。
