# Python 赛时实现配方

本手册是 Skill 自带的原创工程与验证规则，不读取作者的代码库或外部案例。代码必须针对本届模型合同重新实现，依赖是否可用要在每次运行中检测。

## 1. 最小工程结构

```text
contest-work/
├── config/
├── src/
├── tests/
├── inputs/       # 只读副本或清单
├── outputs/
├── figures/
└── logs/
```

- `src` 分离读取、清洗、特征、模型、评价和导出。
- 配置文件保存输入、输出、seed、参数、容差和模型版本。
- 命令行入口不得依赖 Notebook 状态或交互式输入。
- 原始附件只读；所有派生文件写入工作目录。

## 2. 确定性与血缘

每次运行记录：

- Python 与操作系统版本；
- 实际导入包版本和求解器；
- 配置完整内容与哈希；
- 输入文件大小、SHA-256、schema 和行数；
- `seed`、切分索引和重复次数；
- 开始/结束时间、退出状态、日志和输出哈希。

固定 `random`、NumPy 以及实际使用库的随机源。排序前显式指定稳定键；类别编码和时间索引不要依赖文件自然顺序。

## 3. 数据读取断言

读取后立即验证：

```python
required = {"id", "time", "value"}
missing = required.difference(df.columns)
if missing:
    raise ValueError(f"missing columns: {sorted(missing)}")
if df["id"].isna().any():
    raise ValueError("id contains missing values")
```

实际项目还应断言：

- 主键唯一性和合并前后行数；
- 数值范围、单位和正负方向；
- 时间能解析、频率与排序正确；
- 枚举类别没有未知拼写；
- 缺失、重复和异常数量符合合同；
- 结果模板字段、顺序和精度可满足。

不要因方便而静默删除坏行。每一种清洗都保存规则、数量和影响。

## 4. 正确的数据切分

| 数据关系 | 切分 |
|---|---|
| 独立同分布且类别不平衡 | 分层切分 |
| 同一主体多条记录 | 按主体分组切分 |
| 时间序列 | 前推或滚动切分 |
| 空间邻近样本 | 空间块或区域切分 |
| 小样本 | 交叉验证并报告分布 |

填补、缩放、降维、过采样和特征选择只能在训练部分拟合。使用 Pipeline 或显式函数保证顺序。预测时不可获得的特征必须删除。

## 5. 实现路线

| 任务 | 首选基础实现 | 增强条件 | 回退 |
|---|---|---|---|
| 线性/整数优化 | SciPy/可用的规范求解器 | 只有 solver 预检通过才使用额外框架 | 可行贪心、松弛或简化模型 |
| 回归/分类 | scikit-learn 线性、树 | 主模型稳定超过 baseline | 透明线性/规则模型 |
| 时间序列 | 朴素、季节朴素、指数平滑 | 历史长度足够且滚动验证通过 | baseline + 情景区间 |
| 评价/排序 | NumPy/Pandas 实现方向、缩放、等权 | 权重有依据且敏感性通过 | 等权或等级区间 |
| 图网络 | NetworkX 或自写最小标准算法 | 图规模和依赖允许 | 小图/简化图交叉核验 |
| 仿真 | `numpy.random.default_rng` 向量化 | 分布、重复数和收敛有依据 | 确定性上下界或三情景 |
| 图像/几何 | 已安装的基础图像库或解析几何 | 标定和标签验证充分 | 半自动点位或几何边界 |

没有必要时不在赛时安装大型依赖。依赖缺失不得阻断已经定义的 baseline。

## 6. 优化结果复核

不要只相信求解器对象。另写验证函数：

```python
def verify_solution(x, objective, constraints, tol):
    value = objective(x)
    violations = [c.name for c in constraints if c.violation(x) > tol]
    if violations:
        raise ValueError(f"constraint violations: {violations}")
    return value
```

同时记录求解器状态、上下界/间隙（若有）、时间限制和容差。启发式结果称为“已验证可行解”或“当前最好解”，除非有证据证明最优。

## 7. 数值稳定性

- 对量级差异大的特征和优化系数做有依据的缩放。
- 用线性求解代替显式矩阵求逆。
- 每一步检查 NaN/Inf、空数组、零方差、除零和对数定义域。
- 浮点约束使用合同容差，不用完全相等。
- 病态矩阵记录条件数或采用正则化/降维。
- 计算概率后检查范围与归一化；计算权重后检查和为 1。
- 时间和距离计算明确坐标系、时区及单位。

## 8. 最小测试集

每个模型至少包含：

1. 合成冒烟数据：验证入口、字段和文件生成；
2. 已知小实例：可手算或枚举，验证公式和约束；
3. 边界测试：空、单样本、重复、极值、不可行；
4. 性质测试：概率和、守恒、单调性、非负、容量；
5. 泄漏测试：切分索引和特征时点；
6. 输出合同测试：文件名、字段、行数、排序和精度。

测试失败时不得生成 `FROZEN` 标记。

## 9. 机器可读输出

至少保存：

- `metrics.json`：baseline 与主模型同口径指标；
- `predictions.csv` 或 `decisions.csv`；
- 图对应的源数据；
- `config-resolved.json`；
- `environment.txt`；
- `run.log` 与异常 traceback；
- 输入与输出 `sha256` 清单；
- 复现命令。

图表不得成为唯一结果载体。论文中的每个数字都应能在机器可读输出中定位。

## 10. 冻结与降级

- 新进程按记录命令重跑成功后才能冻结。
- 主模型超时、异常、数值不稳或未稳定超过 baseline 时按合同回退。
- 降低仿真次数或搜索规模时，报告区间或最优性限制。
- 任何代码、数据、参数或包版本变化都创建新 `run_id`，旧结果和论文内容标记 `STALE`。
