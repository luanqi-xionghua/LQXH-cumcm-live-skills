# CUMCM 重复与独立复核协议

本协议用于首次结果冻结后的赛时复核。目标是降低代码、数据、模型和叙事共同出错的概率，不把“同一错误重复两次”误当成正确。

## 1. 复核证据层级

由强到弱选择：

1. 独立公式、独立实现或另一求解路线得到一致结果；
2. 小实例枚举、手算、代回原式或逐约束重算；
3. 全新进程使用冻结输入可复现；
4. 参数、网格、步长、seed 和边界扰动后结论稳定；
5. 量纲、守恒、单调性、上下界和常识范围检查；
6. 仅凭“图像合理”或“符合直觉”。

第 6 层不能单独通过任何关键结论。Round B 不能调用主模型的结果汇总函数，否则可能共享同一错误。

## 2. 首次复跑

同环境必须同时满足：同一台设备、同一操作系统及版本、同一 Python/MATLAB 运行时版本、同一关键数值库版本与 BLAS 后端或 MATLAB 工具箱版本，以及同一线程配置。任一项不同即视为跨设备复核。跨设备不是新增的第三轮，只是在复核实际发生于不同环境时启用预声明容差和环境指纹政策。

固定并记录：

- 代码与配置哈希；
- 数据文件、schema、单位和哈希；
- 环境、依赖、求解器、线程数和平台；
- seed、重复次数、停止条件和数值容差；
- 首次结果目录与机器可读输出。

同环境 Round A 在新进程执行原命令，确定性结果要求精确一致，确定性文件比较 SHA-256。跨设备复核，或已经预声明为浮点/随机的结果，CSV/TSV/JSON 数值才可按事先声明的容差比较。日志、时间戳等允许变化的文件必须明确使用 `--ignore` 排除，不能事后忽略失败文件。

示例：

```bash
python3 scripts/compare_runs.py \
  /work/run-initial/results \
  /work/run-recheck-a/results \
  --rtol 1e-9 \
  --atol 1e-12 \
  --ignore "runtime.log" \
  --json
```

示例中的 `--rtol` 与 `--atol` 仅适用于跨设备复核或预先声明为浮点/随机的结果，不得用于放宽同环境 Round A。跨设备两侧必须记录设备、OS 及版本、Python/MATLAB 版本、关键数值库与 BLAS 后端、线程数和 CPU 架构；缺少环境指纹时不能计入 `PASS`。

脚本退出码：

- `0`：所提供目录在声明规则内一致；
- `1`：文件集合、数值、结构或哈希存在差异；
- `2`：参数或路径错误。

脚本通过不代表模型与结论正确，只完成 Round A。

## 3. 独立复核的选择

| 任务 | 首选独立复核 |
|---|---|
| 回归/预测 | 从原始预测与真值独立重算指标；滚动切分；朴素 baseline |
| 分类 | 独立混淆矩阵、阈值、类别指标；按主体/时间重新核对切分 |
| 聚类 | 扰动/重抽样稳定性；用原始变量重建簇画像 |
| 评价/排序 | 独立实现方向化、标准化、权重和得分；等权与扰动排名 |
| 连续优化 | 独立代入目标与全部约束；多初值；上下界 |
| 整数优化/调度 | 小实例枚举/精确解；逐项检查指派、容量、顺序和时间窗 |
| 仿真 | 多 seed、收敛、分位数/区间；确定性上下界 |
| 动力系统 | 量纲、守恒、初边值、离散步长；替代积分器 |
| 图网络 | 逐边成本、方向、容量、连通；小图手算/另一算法 |
| 几何/图像 | 标定、坐标方向、已知尺度、小样本人工复核、误差传播 |

每个小问至少有一个直接回答题面的最终结果通过独立复核。

## 4. 结论与亮点反向核对

从摘要候选、核心表和图、结论与 `CONTRIB-*` 各抽取关键主张：

```text
paper candidate
-> RID/FIG/TAB/CONTRIB
-> verification check
-> frozen RUN
-> MODEL/config
-> DATA/题面或明确假设
```

比较数值、方向、单位、有效数字、样本范围和统计口径。`CONTRIB-PROVEN` 还必须核对 baseline 对照、证伪实验、量化 `proof` 与 `cost_risk`。

## 5. 差异分类

| 类型 | 常见信号 | 动作 |
|---|---|---|
| 数据 | 行数、主键、单位、时间范围不一致 | 修复数据合同并提升版本 |
| 模型 | 公式、约束、边界或假设错误 | 回到模型合同重新冻结 |
| 代码 | 索引、排序、变量、分支或聚合错误 | 修复源码并全量重跑 |
| 数值 | 未收敛、容差、缩放、NaN/Inf | 调整数值策略并重新验证 |
| 随机 | seed 敏感、方差大、挑最好结果 | 增加重复、报告分布或回退 |
| 环境噪声 | 跨设备浮点末位差异位于预声明容差内，环境指纹完整且结论级不变量一致 | 报告留痕，不生成 `ISSUE-*`，不进入修复循环 |
| 展示 | 取整、单位、图表或手工复制错误 | 从机器输出重新生成 |

差异随问题规模、迭代次数或输入量系统性增大，方向一致且有偏，集中于特定模块/小问，或关闭并行、固定线程数后才消失但原量级仍很大时，属于算法不稳定或实现缺陷，不得归类为环境噪声，必须升级为 `ISSUE-*` 并回传生产角色。

即使数值差异位于容差内，排序与排名、方案选择、分类标签、聚类归属、可行性判定、最优解结构、图表定性结论、论文结论性陈述或 `CONTRIB-PROVEN claim` 任一项跨设备不一致，也必须升级为 `ISSUE-*`。

关键差异一律 P0/P1 阻塞。不得只修改报告中的数字，使它与首次结果“看起来一致”。

## 6. 修复循环与停止

```text
发现差异
-> 记录 ISSUE
-> 修复上游
-> 版本提升
-> 旧证据/亮点/论文 STALE
-> 新冻结
-> Round A
-> Round B
-> 风险定向复核
```

默认最多 3 个循环。达到最晚切换时间仍未通过时：

- 优先退回已经完成全套复核的 baseline；
- 缩小结论、扩大不确定性或删除未证亮点；
- 关键答案没有可验证版本时输出 `BLOCKED`。

不能为了追求 PASS 无限调参、放宽容差或删除不一致样本。

## 7. PASS 的含义

`PASS` 表示：

- 同一冻结版本通过可复现复跑与独立复核；
- 关键结果、约束、不变量和追踪链在声明容差内一致；
- 跨设备时，环境指纹完整、浮点结果在预声明容差内一致，且全部结论级不变量完全一致；
- 已知差异、边界与未覆盖范围已披露。

`PASS` 不承诺跨任意设备逐位一致，只承诺在报告声明的环境与容差内一致，且结论级不变量一致。它也不表示题面解释一定唯一、假设一定真实、数据没有未知偏差，或所有未测试情景都正确。论文和最终审计必须保留这些边界。
