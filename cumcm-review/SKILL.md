# CUMCM Review — 论文独立审查

## 定位与原则

- **只读**：默认不修改任何论文/代码/结果文件；审查只产出报告。
- **defect-first**：先列问题，再给总体评价；没有发现就说没有，不编造凑数（借鉴系统 review-agent 原则）。
- **分级**：`P0` 提交级阻塞（数字不可回溯/规则硬违规/关键结果无法复现）；`P1` 应修复（逻辑矛盾/过度声称/图表缺失/合规风险）；`P2` 建议改进（表达/排版/参考文献细节）。
- **结论不冻结**：cumcm-review 是“人可读的审查报告”，不作为正式提交的合规结论；正式审计以 cumcm-live-final-auditor / cumcm-t2 stage7 为准。
- **规则依赖**：合规判定必须有当届官方规则（文件/链接/用户提供）；没有 → 标注“未核验”，不推断。

## 触发方式

用户在对话框输入以下任一即触发：
- `cumcm-review` / `cumcm review`
- `审查论文` / `评论文` / `review paper`

## 输入定位（自动发现，可手动指定）

1. 若用户给出路径，直接用该路径（论文 PDF / 论文目录 / 提交包）。
2. 否则自动发现当前工作区：
   - `outputs/`、`submission/`、`paper/`（论文包）
   - `results/`（frozen_numbers.json、all_results.json、figure-manifest.md）
   - 找到最新 PDF（按修改时间）作为审查主对象。

## 工作流

### Step 1：机器预检（客观项，脚本完成）

```bash
python <技能目录>/scripts/review_paper.py --dir <论文包或工作区> [--pdf <主PDF>] [--frozen results/frozen_numbers.json] [--json]
```

预检输出（写 `checks/cumcm-review-precheck.json`）：
- 页数结构：总页数、第 1 页是否含“摘要/关键词”、第 2 页是否为目录/正文、正文起止页
- PDF 文本质量：`??`、`TODO`、`【待复核】`、内部文件名（RESULTS.md / frozen_numbers / R2025B 等）出现次数
- 强词扫描：首次提出 / 完美 / 最优 / 首创 / 填补空白 / 100% 等
- 图表完整性：`figures/*.pdf` 数量、drawio/tex 源与 PDF 并存情况
- 数字一致性（有 frozen_numbers 时）：关键数值是否出现在 PDF 文本中（缺失则标 WARN）；**兼容 `numbers` 列表与嵌套 dict 两种 frozen schema；提取到 0 个数值 → FROZEN-SCHEMA WARN，绝不静默 PASS**
- 图片引用完整性：`paper/` 与 `outputs/` 下 tex/MD 引用的图片路径 vs 实际文件 diff（IMG-REF-MISSING，防“图没拷进包/图缺失”）
- AI 使用记录：`AI_USE_LOG.md` 是否存在（AI-LOG-MISSING，国赛需随论文披露）
- 提交包结构：submission/ 下 论文/代码/数据/支撑材料 是否齐全
- 三方一致性核对（代码 ↔ 数据 ↔ 论文）：检测到 `code/` 或 `results/` 时自动调用 `scripts/consistency_check.py`——① 代码常量（n/seed/波段/阈值）vs 论文文本；② 冻结数值 vs 论文文本（容差 ±0.1%）；③ 数据行数/范围 vs 论文；④ 结果 JSON 数值 vs 论文。输出写 `checks/cumcm-review-consistency.json`，问题计入预检报告
- 兼容细节：关键词检测兼容“关键词/关键字”两种写法；目录位置不固定（扫描第 2-4 页，报告 toc_page；关键词在第 2 页提示摘要超 1 页）

### Step 2：深审（LLM 本体，9 维度）

按维度逐项审查，每项结论必须给“位置 + 证据 + 置信度（高/中/低）”：
1. **数字可回溯与可信**：关键数字（摘要/核心表/结论）能否追溯到 frozen_numbers/RID；无标识的数字是否可疑。注意：**“可回溯”只证明没抄错，不证明没算错**——数字本身的可靠性由维度 9（方法学健全性）补充审查
2. **跨节逻辑一致性**：摘要↔正文、各章结论、模型假设↔使用、符号表↔正文（专查跨节矛盾与术语不一致）
3. **合规性**：摘要 ≤1 页、正文页数（官方规则）、目录、匿名、附录完整性、AI 使用记录
4. **排版质量**：图宽档位统一、图题“图N：/表N：”格式、overfull、图表渲染异常（箭头缺失/裁切/乱码）
5. **反AI五查**：元叙述泄露、过度声称、太完美数值、模板指纹、长表格。**伪精确检测**：关键结论（最优时点/AUC/敏感度等易受设定影响的数值）若只有点估计、无区间/置信度/对照，标 WARN（如“14.6 周”应伴随 Bootstrap CI 或变体区间）
6. **图表完整性**：整体流程图/每小问流程图/机理图齐备、每图每表被正文 `\ref` 引用
7. **文献与对照**：引文真实支撑相邻陈述、同题/同类研究差异是否主动披露（如折射率取值区间）
8. **可复现性**：代码/数据/结果一致、seed 与环境记录、run-manifest 完整
9. **方法学健全性**（v1.1 新增，重点防“可回溯但算错”）：① 多重共线性——VIF>10 的模型是否被处理/说明（如 BMI=体重/身高² 场景）；② 删失/缺失数据的不可识别性——左删失、右删失比例是否报告，关键结论是否做敏感性分析（删失边界/阈值/分布假设）；③ 阈值与超参数泄漏——Youden/最优阈值是否在训练集内选择，是否按个体分组交叉验证；④ 小样本结论——n<10 的组是否给出置信区间/并组稳健性，而非仅点估计；⑤ 模型选择——是否用“简单够用”模型而非为追求差异引入不稳定设定（对照 MODELING_REPORT 的“方法唯一性”声明）

### Step 3：输出

1. **详细报告**写 `checks/cumcm-review.md`（模板见 `assets/review-report-template.md`）：
   - 审查对象（PDF 路径 + SHA-256 + 页数）+ **审查基线**（可选：上一版 PDF/frozen 的 SHA，用于迭代式差异审查）
   - P0/P1/P2 问题清单（每项：位置/证据/置信度/**结构化修复建议**：受影响上游产物 contract/model_freeze/run_id + 建议重跑命令，衔接 cumcm-t2 回传机制）
   - 9 维度逐项结论（PASS / WARN / FAIL / 未核验，含方法学健全性）
   - 总体评估（优点 3-5 条 + 风险 3-5 条）
   - 若论文含 `MODELING_REPORT.md`，附“五交接契约对照”（结果约束/预期行为/异常预案/方法唯一性/验证检查点）——见维度 9
2. **对话框摘要**：直接给出 Top 5 问题（严重度 + 一句话 + 是否值得修），以及“是否需要我按 P1 修复”的询问（不自动修）。

## 与 cumcm-t2 的协作

- cumcm-t2 stage9 复盘可提示使用 cumcm-review 做赛后审查；
- 审查发现的新问题类型 → 建议回灌到 cumcm-t2 的检查清单/规范（这是 B 题模式：自评问题 → v1.x 硬规则）。

## 边界

- 默认只读；用户明确要求“修复”时，修复前先列修改计划并逐项确认。
- 不执行外部 `.exe/.lnk/未知二进制/Office 宏`。
- 不引用其他竞赛规则判断国赛合规。
- 审查深度受上下文限制：38 页论文采用“脚本预检 + 分节深审”，报告只保留 actionable 项。
