# 赛时拆题与问题合同手册

本手册是 Skill 自带的原创决策规则，不依赖历届论文、教材、作者电脑或网络。它只帮助整理本届题面；题面、附件和当届官方规则才是事实来源。

## 1. 证据分层

给每条陈述标记一种类型，避免把推测写成题面事实。

| 类型 | 定义 | 能否直接进入模型 |
|---|---|---|
| `FACT` | 题面、附件或官方规则明确给出 | 可以，并记录位置 |
| `INTERPRETATION` | 对题意的解释 | 需说明依据并检查歧义 |
| `ASSUMPTION` | 为闭合模型而增加的假设 | 需说明影响和敏感性 |
| `DECISION` | 团队选择的算法、阈值或评价口径 | 需给选择理由和替代项 |
| `UNKNOWN` | 尚未确认的信息 | 不得偷偷补齐 |

证据优先级：当届官方规则与题面 > 当届附件字段说明 > 团队对原始数据的可复核检查 > 内置通用经验。

## 2. 从任务动词识别交付类型

| 题面动作 | 主要交付 | 常见最低验收 |
|---|---|---|
| 描述、刻画、分析现状 | 统计量、结构或规律 | 样本范围、单位、异常处理可查 |
| 判断影响、解释关系 | 效应、关联或机制 | 控制变量、区间、因果边界 |
| 预测、估计未来 | 预测值与区间 | 样本外误差、无未来泄漏 |
| 分类、识别、判定 | 标签或概率 | 混淆矩阵、阈值、分组切分 |
| 聚类、分群、画像 | 群体与解释 | 稳定性、边界样本、群体画像 |
| 评价、排序、优选 | 得分、等级或排名 | 指标方向、权重与敏感性 |
| 优化、调度、配置 | 满足约束的方案 | 目标与全部约束独立复核 |
| 仿真、演化、传播 | 状态轨迹或分布 | 边界、守恒、多 seed、收敛 |
| 设计、提出建议 | 条件式方案 | 与模型输出一一对应、写明失效条件 |

一个小问有多个动作时拆成链。例如“预测需求并制定配送方案”拆成“预测输出 → 优化输入”，分别设置验收。

## 3. 构造问题签名

每个小问都写全：

- `object`：研究对象和观察单位；
- `scope`：空间范围、时间范围、粒度；
- `task`：要描述、预测、判别、评价、优化还是仿真；
- `inputs`：原始字段和上游结果；
- `outputs`：数值、标签、排名、路径、方案、图表或文件；
- `variables`：状态量、决策变量、参数和观测量；
- `constraints`：容量、预算、顺序、整数、时间窗、守恒和边界；
- `uncertainty`：抽样、测量、参数、随机过程或情景；
- `acceptance`：能被代码或人工复核的通过条件。

若 `outputs` 或 `acceptance` 写不清，先阻断模型选择。

## 4. 建立附件与数据合同

对每个文件记录：

| 字段 | 要求 |
|---|---|
| `data_id` | 稳定标识，例如 `DATA-Q1-01` |
| 文件与角色 | 题面、输入、字典、结果模板、媒体或规则 |
| 表与字段 | Sheet、列名、类型、单位、编码 |
| 粒度与主键 | 一行代表什么，主键是否唯一 |
| 范围 | 时间、空间、对象、样本量 |
| 缺失与异常 | 数量、机制、处理权限 |
| 对齐 | 时间戳、坐标、实体 ID、频率 |
| 只读证据 | 路径、大小、哈希、版本 |

优先检查：

1. 同名字段单位是否一致；
2. 百分数、比例和百分点评价是否混用；
3. 日期、时区、采样频率和排序是否明确；
4. 重复主键、合并膨胀和缺失键；
5. 特征生成时间是否晚于预测时点；
6. 结果模板是否限定行数、字段和精度。

## 5. 画小问依赖图

把工作拆成四类节点：

- 公共数据产品：清洗表、距离矩阵、特征表；
- 串行依赖：上游结果是下游输入；
- 可并行支线：共享输入但交付独立；
- 汇合门：多个结果都冻结后才能成稿。

每条边写清：

```text
producer -> artifact_id -> schema/version -> consumer
```

禁止仅写“Q2 依赖 Q1”而不说明依赖哪个字段或文件。

## 6. 最低可交付路线

每个小问建立三层模型阶梯：

1. `baseline`：最简单、可运行、可解释、可复核；
2. `candidate`：只在能增加精度、机制解释或约束处理能力时加入；
3. `fallback`：依赖缺失、超时或验证失败时能按时交付。

为每层记录数据要求、评价指标、资源预算、停止条件和最晚切换时间。没有 baseline 的复杂路线不得进入编码。

临近截止时执行全局配平：先保证每个小问都有能回答题面、能复核、能写入论文的最低实质答案，再把剩余时间投入单问增强。若某问只能使用简化模型，必须同时写明边界与回退，不得用前两问的高完成度掩盖后续空白。

## 7. 选题与切题评分

建议用 0–5 分评估：

- 附件完整性；
- 小问能否形成闭环；
- 可构造独立验证；
- 团队能否实现 baseline；
- 主模型依赖与算力风险；
- 论文能否清楚解释；
- 剩余时间能否覆盖实现、复跑、成稿和终审。

总分只是辅助。规则不明、关键附件缺失或无法验收属于硬阻断，不能用其他高分抵消。

## 8. 交接前硬检查

- 每个未知项都显式列出。
- 题面硬约束、团队假设和算法选择没有混写。
- 每个小问都有机器可复核输出。
- 依赖图中的产物有版本和负责人。
- baseline、候选、回退与切换时间齐全。
- 每个小问都有最低可提交实质答案、负责人、状态和最晚完成时间；任一小问空白则标记 `BLOCKED`。
- 问题合同变更会触发版本提升和下游 `STALE`。

内置经验不能替代本届证据；无法从题面或实际数据确认的内容保持 `UNKNOWN` 或 `BLOCKED`。
